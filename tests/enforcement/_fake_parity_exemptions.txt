# Put a `# parity-exempt: <rationale>` comment on the line directly above the
# class. The walker reads it there, and the rationale bar is the same one this
# file enforces: at least 30 characters, no blanket phrases.
#
#     # parity-exempt: subset shim for nats.js.KeyValue exposing only the get/put/create/update/delete surface; full KeyValue carries history/watch/purge
#     class _FakeKv:
#
# ONE LINE, however long. The walker takes the first non-blank line above the
# class and stops, so a rationale wrapped onto a second comment line exempts
# nothing and reports `no_declaration` -- and ruff does not reflow comments,
# so nothing will tell you.
#
# Entries here are keyed `path:LINE:symbol`, and that line number is the problem:
# it is a property of the file's layout, not of the fake. Adding one import to a
# test module shifts every fake below it and the gate then fails with
# "fake has no parity declaration" -- naming the wrong defect, for a fake nobody
# touched, pointing at a declaration that does exist. It also cannot notice when
# the file it names is deleted; three entries here outlived their module.
#
# The `path:*:symbol` wildcard dodges the shift but keeps the other half of the
# problem: the rationale still lives away from the class it describes, where a
# reader of the fake will not find it and an author of the fake will not update it.
