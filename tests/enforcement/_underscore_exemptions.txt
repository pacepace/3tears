# underscore-access exemptions file.
#
# every entry is an exact (file, SCOPE, symbol, occurrence) key. each entry
# requires a preceding '# rationale: <specific reason>' line. "internal
# access needed" is not a rationale.
#
# format:
#   # rationale: why this access has no public alternative
#   path/relative/to/repo-root.py:Class.method#0:_private_symbol
#
# the middle field is the qualname of the scope enclosing the access, or
# `<module>` at module level, plus the ordinal among same-scope same-symbol
# accesses. it is NOT a line number, and that is the point: a line number is a
# fact about the file's layout, so an edit anywhere above an entry silently
# stopped it matching and this ledger's own checks then reported the original
# violation against code nobody had touched. that fired twice in one session --
# a comment insertion, then a one-line import -- and each time the remedy was
# "re-run the regeneration", which works and teaches you to re-run it without
# reading what changed. that is the state in which a genuinely wrong entry gets
# regenerated straight past.
#
# the ordinal is still there because two accesses in one scope routinely have
# two different reasons -- a line that reads a value and a line that asserts on
# it. dropping it collapses them and the second rationale is replaced by a copy
# of the first at the next regeneration; that happened, and
# `test_two_accesses_in_one_scope_keep_their_own_rationales` pins it.
#
# inserting an access BEFORE an existing one in the same scope still renumbers
# that group. ordinals cannot avoid it. the blast radius is one
# (file, scope, symbol) group rather than every entry below a line.
#
# maintained in lockstep with ruff's per-file-ignores for SLF001, wherever
# ruff reads them from -- the root pyproject.toml, and any nested ruff.toml,
# which is a FULL override the root file cannot reach past. every exemption
# here must have a matching ruff ignore so the two systems agree. no count of
# what this file CURRENTLY holds, anywhere in this header: it promised "the five
# sidecar ones" when the file had none, and again when it had eighty-nine.
# Figures describing a past state are fine -- they report what was, and cannot
# go stale.
#
# NOTE ON CHECKING: these keys ARE checked, in both directions, by
# tests/enforcement/test_underscore_exemptions_resolve.py -- every entry must
# name an access the file still has, and every private access on a
# per-file-exempted path must have an entry. That closes the drift this note
# was originally written to warn about: entries under such a path used to be
# documentation nothing read back, since the underscore walker scans
# packages/*/src only and never enters a tests/ tree.
#
# They no longer drift on an edit above them. What still requires regeneration
# is a genuinely NEW access, or one that moved to a different scope. Regenerate
# rather than hand-edit -- one command, which carries every rationale forward by
# the same key the entries are written in, so only a new access needs new text:
#   uv run python scripts/regen-underscore-exemptions.py
# It reads EVERY ruff config, not just the root pyproject.toml. Reading only
# the root is how five reviewed sidecar entries were deleted without anything
# noticing: packages/scrape/sidecar/ruff.toml is a full override the root
# cannot reach past.
#
# One trap in that procedure, learned the hard way: an inline `# noqa: SLF001`
# in a file that ALSO has a per-file ignore is redundant to ruff and invisible
# to this regeneration -- ruff honours the pragma and reports nothing, so the
# access silently never reaches this file. Six entries went missing that way.
#
# tests/enforcement/test_no_redundant_slf001_pragmas.py now enforces this: a
# path with a per-file SLF001 ignore may not also carry an inline pragma. It is
# the one direction a consistency check cannot cover, since a blinded access is
# never flagged in the first place.
