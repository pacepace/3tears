# Planner-prompt rule ledger

**For:** maintainers editing `plan_prompt.py` (`EVAL_REPORT_PLAN_DEFAULT`, the report planner's seed prompt).
**Answers:** what each numbered rule is there to prevent and where it came from, so a rewrite does not drop a rule
without knowing what it cost to learn.

**How to use it.** The prompt is budgeted at 15,500 characters and 13 rules, the contract
`tests/test_plan_prompt_budget.py` declares (`CHAR_BUDGET` and `RULE_BUDGET`); both ceilings only fall, and the test
fails past either. A rule is a numbered entry under the `RULES` heading; the paragraphs above it are not counted. A change that
adds a rule names the rule it replaces or absorbs, and edits this table in the same commit. A clause added inside a
rule gets its reason added to that row.

**The table is checked against the prompt.** `tests/test_plan_prompt_budget.py` reads each rule's number and heading
(its opening sentence, up to the first full stop, without it) from the prompt, and each row's `#` and `Heading` from
this table, and fails unless the two lists are equal.

**What a rule is.** Interpretation only: what to conclude, how firmly, in what order, what to recommend, which part
of the page says it. Code owns the shape (the planner contract sent as `response_format`, whose enums are the
vocabulary), every number (figure keys, whose grammar code appends), and every fact
(`analysis/report_plan_facts.py`: the signals and shape, the spine, masthead, arm colours and tags, the arms key,
chart levels, units and axes, the flag's disclosures and what it weakens, the options columns, the full-results
tables, ids, a durable claim's keys). Whether a rule binds is measured by evaluating the planner (the planner's eval), never by checking that a
sentence is present.

**Where the rules come from.** The prompt is new with the report plan (the plan replaces the memo as the one writer,
owner ruling 2026-10-25), so no rule here has a planner failure behind it yet. Each is either GENERATOR.md's page
contract and reading rules, which the reference memos were built and reviewed against, or a rule of the analysis
writer's prompt (`GEN_PROMPT_RULES.md`), compressed, whose recorded failure carries over because the planner reads
the same evidence. "Writer rule N" points at that ledger's row for the incident.
