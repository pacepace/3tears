# Writer-prompt rule ledger

**For:** maintainers editing `gen_prompt.py` (`EVAL_ANALYSIS_GEN_DEFAULT`, the analysis writer's seed prompt).
**Answers:** what each numbered rule is there to prevent, so a rewrite does not drop a rule without knowing what
it cost to learn.

**How to use it.** The prompt is budgeted at `PROMPT_CHAR_BUDGET` (28,000 characters) and `PROMPT_RULE_BUDGET`
(15 rules), and both ceilings only fall; `tests/test_gen_prompt_budget.py` fails past either. A rule is a numbered
entry under the `RULES` heading; the paragraphs above it are not counted. A change that adds a rule names the rule
it replaces or absorbs, and edits this table in the same commit. A clause added inside a rule gets its reason added
to that row.

**The table is checked against the prompt.** `tests/test_gen_prompt_budget.py` reads each rule's number and
heading (its opening sentence, up to the first full stop, without it) from the prompt, and each row's `#` and
`Heading` from this table, and fails unless the two lists are equal. So a rule added without a row fails, a row
left behind for a deleted rule fails, and renumbering, reordering or rewording a heading fails until the row
moves with it.

**What a rule is.** Interpretation only (what to conclude, how firmly, in what order, which chart). Code owns the
shape (the schema sent as `response_format`) and every number. Whether a rule binds is measured by evaluating the
report writer, never by checking that a sentence is present.

## The rules

Reasons come from the private campaign history the engine was extracted from (summarised, not published) and from
this package's git log. "Reason not recorded" means no source states why; do not invent one.

| # | Heading | Rule | Failure it prevents | Why |
|---|---------|------|---------------------|-----|
| 1 | RANK ON TELEMETRY, NOT JUDGE SCORES | Rank on telemetry, not judge scores: goal checks first, latency on the mean with the tail beside it; a judged comparison stands only where `multiple_comparisons` separates it; an absolute judged claim needs a `calibrated` tier; quote bar `decision`s, never recompute them | A memo headlined "no quality was measured" over a fully judged campaign; memos written without one mechanical verdict | Judge bias mostly cancels across arms but not in an absolute claim, so comparisons are reportable before calibration and absolute claims are not. Later clauses: an unproven goal check may pass for doing nothing (a do-nothing candidate printed "passed 8/8" unmarked); no p95 below 13 observations (no order statistic is median-unbiased there); tiers decided on confidence bounds (point estimates over-awarded); an `undecided` bar is neither cleared nor failed (#593). The `verdict_order` clause: reason not recorded |
| 2 | A SHORTER TAIL CAN BE BOUGHT BY GIVING UP | Every latency claim carries the delivery rate for the same arms; `n_zero` is a proxy for declines, not a count | An arm bought a shorter tail by declining work, and quality was called "unhurt" while its failure rate went from 0% to 13% | A duration over delivered turns cannot see work that was never done |
| 3 | RANK ON THE SCOPE THAT MATCHES WHAT WAS TUNED | Rank on the scope that matches what was tuned; a scope divergence is its own finding that bounds the ranking one; check a model-call swing against provider throughput | A subsystem change ranked on whole-turn latency picked an arm whose subsystem had not moved and whose failures had risen; a ~205 s swing read as a lever effect was provider throughput drifting across sequential arms | A whole-run measure cannot attribute a movement to the part under test. The `p_adjusted` / `not_separated` clause follows the divergence test that replaced "one moved, one did not" (Gelman & Stern). The `level_a`→`level_b` ordering clause: reason not recorded |
| 4 | A LEVER THAT DID NOT MOVE THE METRIC AND A COMPARISON THAT COULD NOT RESOLVE ARE DIFFERENT FINDINGS | An established null and an unresolved comparison are different findings; no null from overlapping intervals; only `equivalent` says alike; `inert` / `unchecked` mechanisms qualify a null; a monotone ordering is weak evidence, never "no trend" | A 33% monotone reduction published as an absence, with a decision to stop tuning the lever | The two findings lead to opposite actions. Later: a lever that never took effect read as a clean null (#577), hence the mechanism check; `equivalent` only via TOST against a declared margin; a campaign with no declared question corrects one campaign-wide family instead of licensing uncorrected separations |
| 5 | COUNT CASES, NOT ATTEMPTS | Count cases, not attempts: separation rests on `n_independent`; intervals are already over cases; an arm's planned `k` is not its delivered repeats | 5 cases × k=3 posed as 15 independent draws; a coverage floor of 1 read as "every arm ran once" while two arms ran k=3 | Repeats of one case are not independent draws (#590 made every interval cluster-aware, so the writer must not recompute over `n`). The bundle states repeats twice, planned and delivered, and the rule had named only one |
| 6 | CONFIDENCE IS A TIER GRADED BY SUPPORT, AND THE RANGE IS THERE TO BE USED | Confidence is a tier graded by support, the range is used, and one clean result never reaches `high` | A false null was published citing the old "one clean result, direction not in doubt" anchor | The anchor licensed high confidence on a single result |
| 7 | THE DESIGN DECIDES WHAT A COMPARISON MEANS; READ `design` BEFORE MAKING ONE, AND NEVER INFER A DESIGN IT DOES NOT STATE | The design decides what a comparison means: contrasts against the control by name, never pooling contrasts that moved different levers; a confound qualifies a claim but may not name a cause; rig confounds first; config provenance; model roles | Pooled contrasts that moved different levers; an inherited value reported as a choice; a confound read as a cause | Thin evidence is the common case, and each clause follows a misread comparison. Later confound kinds: a reasoning-effort word does not hold reasoning fixed across models (#576); one requested model id answered by several served models (#684); a fold no second arm could refute is unverified, not ruled out |
| 8 | STATE EVERY FINDING IN THE DIRECTION THE EVIDENCE SUPPORTS | State every finding in the direction the evidence supports | A refuted claim published at a low tier reads as support to a skimming reader | A low tier does not reverse a claim's direction |
| 9 | CONCLUSIONS ARE THE PRODUCT, WRITTEN FOR A PERSON | Conclusions are the product, written for a person: conclusion first, validity gates first, a headline of at most twelve plain words, a three-to-five-bullet summary that never escalates, a short plain style guide | A headline naming the deciding setting, unusable for configuring the system; a shift between two failure modes framed as improvement; a 25-word headline of config values, a jargon summary, unread answer paragraphs | Owner reviews: "very strong on evidence and very weak on conclusions"; "be clear, don't overly hedge, be human". Later: "about the same" removed from the style list because it invites turning `not_separated` into "no difference"; exploratory labelling of findings resting on unasked readings (`reading_scope`) |
| 10 | A CAVEAT QUALIFIES THE FINDING IT HANGS ON, AND ITS ORDER IS A PRIORITY | A caveat qualifies the finding it hangs on, ordered by what a decision-maker must know first, typed by `kind`; a re-diagnosis is the finding, not a caveat | A caveat that changed the diagnosis sat under the verdict it contradicted, on the wrong finding | A caveat placed elsewhere is not read with the claim it changes. The `immaterial` clause arrived with the materiality threshold, telling the writer an immaterial movement carries no caveat; its motivating failure is not recorded |
| 11 | A DECISION IS ONE PROPOSAL AND A VERDICT ON IT | A decision is one positive proposal and a verdict; one choice is one decision; adopting a non-control arm needs an `improved` reading; never adopt over a `breached` guardrail; a deferral names a specific trigger; an unanswerable question says why, what would settle it and its rough cost | "Stop sweeping X" filed under Rejected; "Adopt A" beside "Reject B" for one choice; generic revisit triggers; an arm marked adopted that no comparison had separated from the control | Each is a decision a reader cannot act on cleanly. An `undecided` guardrail names itself rather than refusing adoption: with no margin a guardrail reads held only about 2.5% of the time under no change, so refusing on undecided would refuse nearly every adoption |
| 12 | NEXT EXPERIMENTS ARE ORDERED BY LEVERAGE, AND LEVERAGE IS ABOUT A DECISION | Next experiments are ordered by leverage, and leverage is about a decision this analysis records | The top-ranked next step was the run that would reopen the decision the memo had just adopted | An experiment that could overturn an adopted decision shows that decision was really deferred |
| 13 | CHECK YOUR WORK, THEN CUT IT, BEFORE YOU RETURN IT | Check your work, then cut it: every claim true of all it names, every tier earned, every named cause checked against its obvious rival, every swept axis named; three to five findings and two or three next steps; a rig fact that changes no conclusion is a caveat; be subject-agnostic | ~2k-word memos with 6–7 findings; a turn-limit finding in every memo; "worse across all models" when one was unchanged; a slowdown blamed on a change when that run started later; high-confidence adoption on 9–12 trials | Owner review: exhaustive writing was counter-productive. It replaced the old "record what the campaign taught about measuring" rule, which produced the turn-limit findings, and kept its axis-naming and subject-agnostic clauses. The output-cap rival named in the cause check: reason not recorded |
| 14 | CHARTS — SELECT ON THE CLAIM, NOT ON THE DATA | Charts: select on the claim, not the data; `none` is a claim; weaken the claim, never the rendering; a caption says what the chart cannot; what each type needs | Half of stored findings carried no chart; data-shape matching picked a type that contradicted the claim; a caption duplicated what the renderer appends | The same rows support several chart types, so only the claim can choose. `timeseries` is offered only when the bundle carries a time axis |

## Not rules, but load-bearing

- **"Every number a reader sees is code's"** (preamble; formerly a rule). It prevents fabricated citations and
  hand-typed figures nobody could find in the evidence. A finding that cites no reading has empty evidence.
- **The figure-reference grammar is appended by the generator** (`prose_refs.reference_grammar`), written from the
  parser's constants. A copy kept in a stored prompt went on teaching each deployment the grammar it was seeded
  with after the parser changed, and every generation there was refused at full cost.
- **No worked WRONG/RIGHT examples.** A model reproduced a prompt's canonical answer with its nouns swapped.
