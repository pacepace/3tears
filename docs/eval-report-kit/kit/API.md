# Kit API

`kit.css` is the visual system: tokens, type, layout, tables, pills, controls. `kit.js` holds the chart and naming helpers. Both are inlined into each page by `scripts/build.py`. The stylesheet fetches nothing: its faces are a local stack (IBM Plex Sans, Sans Condensed and Mono where installed, then the system's, ending in a generic family). The reference memos' sources link Plex from Google Fonts; the package's report pages link nothing.

## Tokens (kit.css)

| Token | Use |
|---|---|
| `--host-font-body`, `--host-font-mono`, `--host-color-text`, `--host-color-muted`, `--host-color-surface`, `--host-color-link`, `--host-color-accent` | **The tokens a host sets**, on the page's `<html>` tag. The kit reads each with its own value as the fallback and declares none of them, so a host's value wins in either theme. They set `--f-body`/`--f-display`, `--f-mono`, `--ink`, `--muted`, `--bg`/`--surface`, `--link` and `--accent`. |
| `--bg --surface --ink --muted --accent --link` | Neutrals and the accent, read from the host tokens. |
| `--ink-2 --sunk --line --base --accent-wash --shade` | Mixed from those by `color-mix`, so a host's palette carries through: secondary text, the sunken tint, rules, the accent's wash, a scroll shadow. |
| `--on-fill` `--on-accent` | Text set on a filled mark (an arm's tag square, a count inside a bar), and on the accent (a pressed segment). A tag's letter and a difference cell's figure take whichever of two inks reads better on their own fill (`kInk`): on-fill or the surface on a tag, ink or the surface on a cell. |
| `--s1 … --s5` | Series colors in fixed order: blue, magenta, teal, indigo, violet, each at 3:1 or more on the page in both themes and 40 degrees or more in hue from the status colours, so an arm never reads as a verdict. The control uses `--ink-2`. |
| `--good --warn --bad` and `*-wash` | Status. Always shown with ✓ ! ✕ and a word (`pill()`). |
| `--seq-0 … --seq-5`, `--seq-t0 … --seq-t5` | Sequential ramp and the matching text color for each step. The dark ramp runs light-on-dark. |
| `--div-neg --div-mid --div-pos` | Diverging ramp for difference heatmaps. |
| `--ground` | The ground a table sits on: the page's `--bg`, a card's or a figure's `--surface`. A table is ruled, never boxed: no frame border, no header fill, a rule in `--ink-2` under its header. |
| `--t-xs --t-sm --t-base --t-lg --t-hero` | The type scale's five steps: 12 px (ticks, captions, chart labels), 14 (tables, notes), 16 (body), 20 (h2, a code page's title, a headline over 90 characters) and 28 (the headline). Nothing is set between them. |
| `--f-display --f-body --f-mono` | Plex Sans Condensed, Plex Sans, Plex Mono, each then the system's faces and a generic family. |

**Outcomes** (how each trial ended, as a stacked bar draws them) never take a series color, since series colors name arms: passed is ink (`--ink-2`), solid, so green means a status pill alone; every failure cause is `--bad` under a texture of its own (`pattern`: `hatch`, `cross`, `dots`, `rows`, `cols`, in that order), so five causes read as five looks and no failure reads as a pass even without color; a loss cause is a neutral, `--base` then `--muted` solid, then each textured. A texture is sparse (12 px apart) over a light wash, so a bar of failures never reads as a block of ink. The legend names every cause in its look.

**Arms** take one color for the whole page, by their letter tag (GENERATOR.md §6.1): the control (`P`) `--ink-2`, the candidates (`A`, `B`, …) `--s1 … --s5` in order, plus a shape (scatter) or the tag in a square (bars), so color is never the only cue.

Dark values are defined twice, under `prefers-color-scheme: dark` (guarded by `:not([data-theme="light"])`) and under `[data-theme="dark"]`, so a host toggle wins both ways. Neither block declares a `--host-*` token.

## Chart data: the `data-chart` contract

A chart is one element. The kit finds it, parses its JSON and draws it; the page carries no chart code.

```html
<div class="chart" data-kind="forest" data-chart='{"domain":[-16,4],"fmt":"+num:0","level":"95%","rows":[…]}'></div>
```

- **Drawing.** `drawCharts()` runs on `DOMContentLoaded` and draws every `div.chart[data-kind][data-chart]`. SVG kinds draw at the element's real pixel width and redraw on resize and once web fonts load; HTML kinds (`gate_matrix`, `lattice`, `heatmap`, `diff_heatmap`, `confusion`, `examples`) draw once and size with CSS. Changing `data-chart` later (`setChart(el, data)`) redraws that chart, which is how an explore control updates one.
- **Refusals.** An unknown kind, JSON that does not parse or is not an object, a missing required field, a color that is not a token, an unknown `fmt`, `shape` or `pattern`, intervals without a `level`, or a number that reaches a style or a size (`width`, `opacity`, `size`, `card_min_rem`, `panel_min_rem`) that is not a finite number draw nothing for that element and log `kit: chart "<kind>" #<id>: <reason>` with `console.error`, so `scripts/check.py` fails the page. The figure's table (the package's `.chart-values`) is then what a reader sees.
- **Null is unset.** A field written as `null` is read as one not written, everywhere: a panel's `null` field inherits the chart's value, as the package's models read it.
- **Pure data.** The JSON holds no functions and no markup. Every string is text: the kit escapes it, so a label, tooltip or excerpt can never add an element. The producer HTML-escapes the attribute value itself (`&`, and the quote it wraps the attribute in).
- **One contract, two sides.** The package's chart models (`threetears.evals.analysis.report.charts`, carried by a `ChartBlock` as its `data`) mirror this contract field for field, and `packages/evals/tests/test_report_kit_charts.py` reads every reference chart as its model and checks it dumps back to the same JSON.
- **Units.** Values are in display units: percentages as 0–100 (85.3, not 0.853), points as points, dollars as dollars, latency in ms or s as the `fmt` says. The kit never rescales.
- **Text, where the producer decided it.** A value may carry its text beside it (`value_text`, `lo_text`, `hi_text` and their kin, below): the figure as printed, unit and sign included. The kit prints that text as it is wherever it would print the value (a note it defaults to, a tooltip, a tile, a cell), and formats a value with `fmt` only where it carries none, so a producer that decides each figure's form once (the package's page does, from the page's number forms) gets it drawn exactly so, never re-rounded by the kit. Tick labels are still the kit's: where the ticks fall depends on the drawn width. A chart without text fields draws as it always has.

### Fields every kind shares

Each kind uses the subset its table lists. The same idea has the same name in every kind.

| Field | Type | Meaning |
|---|---|---|
| `fmt` | string | Named format for values and axis labels: `name` or `name:digits`, with a leading `+` to sign positive values. Names: `num` (plain), `int` (rounded, thousands separators), `pct` (`85.3%`), `pts` (`2.1 pts`), `usd` (no digits, by each amount's size: $0.0450, $0.30, $4.25, $12, $1,208, whole dollars from $10, cents from ten cents, three significant figures below; with digits: fixed; always grouped, a negative amount `-$1,208`), `usdk` ($7.6k), `usdpk` (retired 2026-11-07, read only so a chart stored with it still draws: dollars in, per 1,000 out with the mark, two decimals unless `digits` is given: 0.008 reads `$8.00/1000`; the package writes money per 1,000 replies as `usd` and says the count in the axis title or header instead), `ms` (`513 ms`), `s` (`3.0 s`), `dur` (ms in, `600ms` / `1s` out), `x` (`1.5×`), `k` (`3.1k`). Without digits a value prints as many decimals as it needs, up to two (`usd` and `ms` keep their own rounding). |
| `tick_fmt` | string | Format for axis labels when it differs from `fmt`. |
| `domain` | [number, number] | Axis range in value units. A value outside it is drawn at the edge. |
| `ticks` | number[] | Explicit tick positions. The kit drops any whose label would touch its neighbour at the drawn width. Without it, nice ticks are chosen so no two labels repeat. |
| `level` | string | Interval level, printed on the chart as "`<level>` intervals" ("95%"). A level glossed in parentheses after it keeps its gloss last: "99.7% (95% across 16 comparisons)" prints "99.7% intervals (95% across 16 comparisons)". Required by `forest`, by `bars`, `diverging_bars`, `dot_interval` and `lines` whenever a row or series carries `lo`/`hi`, and by `scatter_frontier` and `gate_scatter` whenever a point carries `x_lo`/`x_hi` or `y_lo`/`y_hi` (GENERATOR.md §5.2). |
| `reference` | {value, label?, kind} | A floor, budget, margin or no-preference point, in value units. `kind`: `floor` (pass at or above), `budget` (pass at or below), `margin` (forest: the band from `value` up to the domain's top is shaded), `no_preference` (diverging bars grow from `value` instead of zero; no line is drawn). `label` is printed beside the line when given: to its right where it fits, else to its left, else wrapped at its spaces to the wider side, so it stays off the level and inside the chart. A label with a word wider than either side is not broken there: it is set against the chart's right edge, across its line. |
| `emphasis` | string | The `id` of the one row, point or cell to emphasize: bold label, ring (scatter) or outline (lattice). |
| `id` | string | On a row, point or cell: what `emphasis` and `paths` name. |
| `color` | string | A token name (`"--s1"`, `"--ink-2"`, `"--seq-2"`), checked against `^--[a-z][a-z0-9-]*$`. Arm identity: the same color for an arm on every chart. |
| `strong` / `muted` | boolean | On a row or point: bold label and note / faded mark. |
| `tip` | string[] | Tooltip lines; the first is set in bold. Each kind has a default when omitted. |
| `value_text`, `lo_text`, `hi_text` | string | On a row, point or cell: its value's and its interval's ends' text as printed (`"-7.6 pts"`, `"85.3%"`, `"$4.60"`), which the kit prints in place of formatting `value`, `lo` or `hi` with `fmt`; formatted with `fmt` where absent. Each kind's other drawn values carry theirs the same way, named after the value: a line's `values_text`, `lo_text` and `hi_text` (one per category), a point's `x_text` and `y_text`, a range row's `from_text` and `to_text`, a cell's `cost_text` (with `cost_unit`), `latency_text`, `detail_text`, a heatmap cell's `low_text` and `high_text`, a confusion matrix's `matrix_text` (row by row, as drawn). A stacked bar's segment and a `reference` may carry `value_text` too, which only the values table prints. |
| `note` | string | Text printed at a bar's end, or a forest's or dot strip's row's right edge; a bar's is printed whole as the `bars` kind row says, a dot strip's wraps at its spaces (two lines at most) in a margin as wide as its widest line, up to 30% of the chart. A forest prints every row's note where every row has one, wrapped at its spaces where it does not fit, else every row's value, so its end labels read alike and never read coarser than the note. |
| `zero_label` | string | On a change chart (`forest`, `bars`, `diverging_bars`, `dot_interval`): what zero is, no change against the control as its rows name it, with its level where every row shares one (`no change vs P · September ($1.89, mean over 294 cases)`), printed at the top of the zero line on a line of its own: beside the line where a side holds it, else over the line on one line inside the chart, else wrapped. A `dot_interval` draws its zero line only with one. A panel's own `zero_label` replaces the chart's. |
| `better` | `"right"`, `"left"` or two strings | On a change chart: which way is better, printed under the axis at the plot's two ends. `right` prints "← worse" and "better →", `left` the mirror; two strings print each under its own end, the left end's first (`["prefers shipped", "prefers lead-first"]`). Where both do not fit on one line, the left one sits a line higher. |
| `short_label` | string | Used when `label` does not fit the label column. |
| `tag` | string | On a bar row: an arm's letter tag, drawn in a square of the row's `color` between the label and the bar, beside the label in the form the `bars` kind row gives it; never in its place. |
| `pattern` | string | On a bar segment or a legend entry: a texture drawn in the `color` over a wash of it, `hatch`, `cross`, `dots`, `rows` or `cols`; solid when absent. |
| `label_width`, `label_width_narrow` | number | Label column in px, above and below 480 px chart width. Default: fitted to the labels. |
| `row_height` | number | Row pitch in px. |
| `height` | number | Plot height in px (scatter, lines). |
| `legend` | [{label, color?, mark?, hollow?, opacity?, pattern?}] | Drawn above the chart (above the grid for small multiples). `mark`: `dot` (default) or `square` (a swatch), `line` (a stroke sample, `opacity` applies), or a marker shape `circle`, `triangle`, `diamond`. A `pattern` draws a textured swatch, as the segments carrying it. |
| `panels` | object[] | Small multiples (`small_multiples_by`). Each panel is `{title, subtitle?, tag?, color?, …kind fields}`, drawn as a figure in a `.mult` grid; the chart's own fields are shared by every panel and a panel's fields override them. `tag` and `color` print the title as an arm chip. A panel carrying only text fields is drawn as a text card. |
| `panel_min_rem` | number | Narrowest panel before the grid drops a column (default 15.5). |

## Functions (kit.js)

All charts draw SVG at the container's real pixel width and redraw on resize. Colors are passed as token names (`"--s1"`), applied through `style`, so theme changes need no redraw. The declarative renderers above are built on these; a page calls them directly only for a chart no kind covers.

|---|---|---|
| `drawCharts(root?)` | | Draws every `div.chart[data-kind][data-chart]` under `root` (default `document`) once and watches its `data-chart`. Runs on `DOMContentLoaded`. |
| `setChart(el, data)` | | Sets `el`'s `data-chart` to `JSON.stringify(data)`, which draws or redraws it. |
| `namedFmt(spec)` | → `fmt(v)` | The formatter for a `fmt` name; throws on an unknown one. |
| `chart(el, fn)` | `fn(el, width)` | Responsive mount. Returns a `redraw()` to call after state changes (explore controls). |
| `svgIn(el, w, h)` | → svg | |
| `S(tag, attrs, parent)` / `H(tag, attrs, html)` | | SVG and HTML element helpers; `attrs.text` sets the text. |
| `lin(d0,d1,r0,r1)`, `logs(...)`, `ticks(a,b,n)` | | Scales and nice ticks. |
| `fmt.pct .usd .s .ms .x` | | Formatters. |
| `esc(s)`, `tipHTML(lines)` | | Escape text for markup; build tooltip markup from text lines (first bold). |

| `textW(text, size?, weight?)` | → px | Text width in the chart font, measured. |
| `placeLabels(items, bounds, obstacles, marks?)` | `items:[{px,py,text,strong?,r?}]` → adds `x,y,anchor` | Tries right, left, above and below its mark (clearing a mark of radius `r`), then nudges up and down; avoids other labels and obstacle boxes `[x0,y0,x1,y1,cost?]` (cost 10 by default; reference lines cost 1, so crossing one beats colliding with a label).
